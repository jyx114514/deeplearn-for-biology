学习蛋白质的语言：从序列表示到功能预测 ​

任务 2.1：认识蛋白质表示与掩码预测 ​

Machine Learning Primer 机器学习基础 ​

我们已经简要回顾了蛋白质的生物学背景，以及它们的功能是如何被编码的。现在，我们转向那些让我们能够真正从蛋白质序列中进行学习的机器学习技术。

Large Language Models 大语言模型 ​

如今，走到哪里都很难不碰到大语言模型（large language model，LLM）。近来许多 AI 领域的突破性模型——例如 ChatGPT、Gemini、Claude 和 Llama——都归属于这一类别。虽然这些模型涉及巨大的工程量，但其背后的基本思想出奇地简单：它们被训练成在给定前文上下文的情况下预测下一个 token（例如一个词或一个字符）。其中存在一些细微的变体——例如掩码语言模型（masked language model），它在训练时随机隐藏一些 token，以鼓励基于上下文的推理——但核心原则保持不变。

现代 AI 中最令人惊讶的发现之一是：如果你在足够多的数据（以总 token 数计）上训练一个足够大的模型（以参数量计），就会涌现出惊人的能力，而无需显式的监督。这些模型会突然能够总结文本、在不同语言之间翻译，甚至创作诗歌和故事这样的创意写作——尽管它们从未被直接训练去这么做。

这为生物学带来了希望。在许多方面，生物学都像语言：DNA 和蛋白质是由离散字母表构建的序列，具有复杂的模式以及依赖上下文的「语法」。通过在大量生物序列语料上训练语言模型——使用同样的「预测下一个 token」目标——我们应当能够学到关于生物信息的丰富表示。

这些习得的表示随后可用于各种各样的下游任务，例如预测蛋白质功能、推断突变效应，或识别结构性质——而且都不需要从头重新训练一个新模型。

在本章后文，我们将探讨迄今最成功的蛋白质语言模型之一：ESM2。

Embeddings 嵌入 ​

语言模型最强大、最通用的输出之一，是它们生成嵌入（embedding）的能力。嵌入是一个数值向量——一串浮点数——它编码某个实体（如一个词、一句话或一条蛋白质序列）的含义或结构。例如，一个蛋白质可能被表示为一个形如 [0.1, -0.3, 1.3, 0.9, 0.2] 的嵌入，它可以以紧凑的数值形式捕捉该蛋白质在生化或结构性质上的某些方面。

来自语言模型的嵌入并非随意的数字——它们被组织成这样的结构：相似的输入会产生相似的嵌入。像 lion、tiger、panther 这样的相关词，会在一个语言学的「语义空间」中聚集成簇。同样地，结构与功能相似的蛋白质序列——例如胶原蛋白 I 和胶原蛋白 II——其嵌入也会在我们或许可称为「蛋白质空间」的地方彼此靠近。

这一思想可以推广到潜空间（latent space）的概念——一个连续的、抽象的空间，其中相似的实体根据学到的模式被放置在彼此靠近的位置。在这样的空间里，我们可以执行强大的操作，例如插值、聚类和生成式设计。对蛋白质而言，潜空间能够捕捉仅凭序列无法看出的功能关系——例如，两个序列和进化历史都极为不同的蛋白质，可能趋同到了相似的功能，因而在潜空间中显得彼此靠近。这些表示还可以通过把未表征的蛋白质与空间中已有注释的近邻进行比较，帮助预测它们的新功能。

提示： 要找出结构或功能相似的蛋白质，你可以用余弦相似度（cosine similarity）来比较它们的嵌入——这是一种衡量两个向量对齐程度的度量，与它们的模长无关。即使序列在氨基酸层面差异很大，这种方法依然有效。通过计算一个查询蛋白质与一组已知蛋白质之间的余弦相似度，你可以在嵌入空间中给最接近的匹配排序。这些排名靠前的结果往往共享功能角色、结构特征或进化历史。

Pretraining and Fine-tuning 预训练与微调 ​

许多机器学习任务共享底层的结构。无论你的目标是检测仇恨言论、回答法学院入学考试题目，还是写一首关于水豚的诗，你的模型首先都需要对语言如何运作有扎实的基础。与其为每个任务都从头训练，我们通常从一个通用模型出发，它已经在一个巨大而多样的数据集上完成了预训练（pretraining）。

预训练赋予模型广泛的知识和通用的能力。对于某个具体应用，我们通常会接上一个更小、更聚焦的训练步骤，称为微调（fine-tuning），在这一步中模型会在某一特定领域的数据集上继续训练。这个两阶段流程如今已成为机器学习许多领域的标准做法，尤其是在预训练语言模型变得日益强大之后。

在这本书的第一个技术性章节中，我们会采取一种略有不同的做法。我们不去微调整个预训练模型，而是把它当作一个冻结的特征提取器（frozen feature extractor）：我们用它的嵌入作为输入，喂给我们将从头训练的一个更小的分类器。这种策略高效、所需数据少，并且仍然利用了预训练模型学到的丰富表示。我们将在后续章节中探讨带有微调的完整迁移学习。

One-Hot Encoding of a Protein Sequence 蛋白质序列的独热编码 ​

把蛋白质序列转换成数值形式的最简单方法是独热编码（one-hot encoding）。它的工作原理如下：

  • 标准氨基酸共有 20 种。
  • 每个氨基酸用一个长度为 20 的二值向量表示，其中只有一个位置为 1（表示该氨基酸的身份），其余所有位置均为 0。
  • 一条蛋白质序列随后被转换成这些独热向量组成的序列——每个氨基酸对应一个向量。

我们用一个玩具示例走一遍：编码这条短蛋白 MALWM（胰岛素前体蛋白的前五个氨基酸）。

首先，定义氨基酸字母代码到整数索引的映射：

python
# 此处的索引顺序是手工约定，和 ESM2 tokenizer 的索引不同。

amino_acids = [
    "R", "H", "K", "D", "E", "S", "T", "N", "Q", "G", "P", "C", "A", "V", "I",
    "L", "M", "F", "Y", "W",
]
amino_acid_to_index = {
    amino_acid: index for index, amino_acid in enumerate(amino_acids)
}
print(amino_acid_to_index)

给定一条蛋白质序列，我们可以把它转换为一个整数序列：

python
# 甲硫氨酸、丙氨酸、亮氨酸、色氨酸、甲硫氨酸。
tiny_protein = ["M", "A", "L", "W", "M"]

]
tiny_protein_indices

输出：

而给定一个整数序列，我们可以把它转换成一个独热编码（见 Figure 2-4）。

在 Figure 2-4 中，我们看到：

  • 得到的矩阵形状为 [5, 20]，其中五行分别对应序列中的一个氨基酸，而每一列代表 20 种标准氨基酸之一。
  • 每一行除了在该氨基酸身份对应的位置上有一个 1 之外，其余全为零，从而保留其类别性质，而不暗示任何数值上的次序或相似性。

提示： 为什么不直接跳过独热编码这一步，而使用氨基酸索引呢？

问题在于，数值索引（比如 3 与 17）会暗示一种人为的次序和相对相似性，尽管氨基酸本身是无序的类别实体，彼此之间并没有有意义的数值关系。独热编码通过为每个氨基酸分配一个不同的二值向量来避免这一点——确保模型把它们视为彼此平等且相互独立，从而避免从任意的索引值中推断出并不存在的模式。

在代码中，我们可以用深度学习框架自带的独热编码工具来得到这个嵌入。下面给出 PyTorch 的实现：

python
# one_hot 生成 [序列长度, 氨基酸种类数]，float 转为浮点表示。
import torch

one_hot_encoded_sequence = torch.nn.functional.one_hot(
    torch.tensor(tiny_protein_indices), num_classes=len(amino_acids)
).float()
print(one_hot_encoded_sequence)

Learned Embeddings of Amino Acids 氨基酸的学习嵌入 ​

在本章剩余部分，我们将使用一个名为 ESM2 的预训练蛋白质语言模型，它由 Meta 在 2023 年发布（ESM 代表 evolutionary scale modeling，进化尺度建模）。这些模型托管在 Hugging Face 平台上。如果你还没有接触过它：Hugging Face 是一个极好的资源，有成千上万个预训练模型可供你使用和探索。

我们稍后会详细探讨 ESM2 模型是如何工作的，但首先，让我们看看它是如何表示单个氨基酸的。我们将使用 Hugging Face 的 transformers 库来访问该模型。ESM2 基于 2017 年提出的 transformer 神经网络架构，该架构已成为建模文本和蛋白质等序列的标准。

提示： 这里使用 PyTorch 和 Hugging Face transformers 来加载 ESM2、提取嵌入，并训练后面的分类器。模型权重和 tokenizer 须事先保存在本地缓存中；离线开关不会自动准备这些文件。

python

#分词器
tokenizer = AutoTokenizer.from_pretrained(model_checkpoint)
#模型
model = EsmModel.from_pretrained(model_checkpoint)
model.eval()

现在，我们用 model.get_input_embeddings() 从模型中提取学习到的 token 嵌入：

python
# 这是输入查表嵌入，尚未融合当前序列的上下文。
"""
model.get_input_embeddings()
获取模型的输入嵌入层（Embedding Layer）

ESM模型的嵌入层是一个矩阵，形状为 (vocab_size, hidden_size)

.weight
获取嵌入层的权重参数

这是一个可训练的参数张量

.detach()
从计算图中分离张量，避免梯度追踪

.numpy()

"""
token_embeddings = model.get_input_embeddings().weight.detach().numpy()
token_embeddings.shape

输出：

text
(33, 1280)

33 个可能的 token 中的每一个都被嵌入到一个 1,280 维的空间中。虽然人类无法直接可视化这样的高维空间，但我们可以应用 t-SNE 或 UMAP 之类的降维技术，把嵌入投影到二维。这样我们就能以更易理解的形式，检视模型是如何组织不同 token 的：

python

from sklearn.manifold import TSNE

tsne = TSNE(n_components=2, random_state=65)
embeddings_tsne = tsne.fit_transform(token_embeddings)
embeddings_tsne_df = pd.DataFrame(
    embeddings_tsne, columns=["first_dim", "second_dim"]
)
embeddings_tsne_df.shape

输出：

text
(33, 2)

可以看到，经过 t-SNE 变换后的数组形状为 (33, 2)，这意味着 33 个 token 中的每一个都被投影到了 2D 空间中。Figure 2-6 展示了这些点的散点图，让我们从视觉上感受模型是如何组织 token 嵌入的：

        "<null_1>",

The ESM2 Protein Language Model ESM2 蛋白质语言模型 ​

既然你对 token 嵌入更熟悉了，我们来讨论 ESM2 模型实际是如何工作的。ESM2 是一个掩码语言模型（masked language model，MLM），这意味着它的训练方式是：反复地在每条蛋白质序列中随机掩蔽一部分氨基酸，并要求模型预测它们。就 ESM2 而言，训练期间每条序列中随机选出的 15% 氨基酸会被掩蔽。Figure 2-8 用可视化方式说明了这一点，并将其与自然语言任务中的掩码语言建模作了对比：

我们把这段代码重写成一个更通用的形式 MaskPredictor，它带有掩蔽序列、做出预测和绘制预测结果的方法：

python
# mask_index 是残基的零基索引，模型位置须加上开头的 <cls>。
class MaskPredictor:
    """使用蛋白质语言模型预测被掩蔽的氨基酸。"""

    def __init__(self, tokenizer, model):
        """用 tokenizer 和预训练模型初始化。"""
        self.tokenizer = tokenizer
        self.model = model

    def plot_predictions(self, sequence: str, mask_index: int):
        """绘制被掩蔽氨基酸的预测概率。"""
        mask_probs = self.predict(sequence, mask_index)
        fig, _ = plt.subplots(figsize=(6, 4))
        plt.bar(list(self.tokenizer.get_vocab().keys()), mask_probs, color="grey")
        plt.xticks(rotation=90)
        plt.title(
            "Model Probabilities for the Masked Amino Acid\n"
            f"at Index={mask_index} (True Amino Acid = {sequence[mask_index]})."
        )
        return fig

    def predict(self, sequence: str, mask_index: int) :
        """返回某一位置上被掩蔽氨基酸的模型概率。"""
        masked_sequence = self.mask_sequence(sequence, mask_index)
        masked_inputs = self.tokenizer(masked_sequence, return_tensors="pt")
        model_outputs = self.model(**masked_inputs)
        mask_preds = model_outputs.logits[0, mask_index + 1]
        mask_probs = torch.softmax(mask_preds, dim=-1).detach().numpy()
        return mask_probs

    @staticmethod
    def mask_sequence(sequence: str, mask_index: int) -> str:
        """在输入序列的指定索引处插入 mask token。"""
        if mask_index < 0 or mask_index > len(sequence):
            raise ValueError("Mask index outside of sequence range.")
        return f"{sequence[0:mask_index]}<mask>{sequence[(mask_index + 1):]}"

Strategies for Extracting an Embedding for an Entire Protein 为整个蛋白质提取嵌入的策略 ​

到目前为止，我们已经探索了 ESM2 模型如何表示单个氨基酸。但许多下游任务——例如预测蛋白质功能——都需要整个蛋白质序列的定长表示。我们如何把一条变长的氨基酸序列，转换成能捕捉该蛋白质整体结构与含义的单个嵌入向量？

常用的策略有以下几种：

拼接氨基酸嵌入（Concatenation of amino acid embeddings） 一种简单的做法是遍历序列中的每个氨基酸，提取它的嵌入，然后把它们拼接成一条很长的向量。例如，如果一个蛋白质长度为 10，每个氨基酸有 1,280 维嵌入，那么就会得到一个长度为 10 × 1280 = 12800 的蛋白质嵌入。虽然这保留了每个氨基酸的细粒度信息，但它有几个缺点：

  • 长度可变（Variable length）：不同的蛋白质会产生不同长度的嵌入，这使模型输入的格式化变得复杂。
  • 可扩展性差（Scalability）：长蛋白质会产生巨大的嵌入。例如，肌联蛋白（titin）——已知最长的人类蛋白质，约 34,000 个氨基酸——会产生一个含 4,300 万个以上数值的嵌入。这对大多数模型来说都太笨重了。
  • 建模能力有限（Limited modeling）：这种做法把氨基酸当作彼此独立，忽略了蛋白质功能核心的上下文关系。

氨基酸嵌入求平均（Averaging of amino acid embeddings） 一种更紧凑的做法是对序列上的 token 嵌入取平均。仍用刚才那个长度为 10、每个嵌入 1,280 维的蛋白质为例，我们对全部 10 个嵌入取均值，得到一个最终的 1,280 维向量。

  • 它的好处是无论蛋白质多长，都能产生固定大小的向量。
  • 它高效，有时也被使用，但同样粗糙——取平均丢弃了次序和相互作用信息。这就像通过把一部小说所有词的词向量求平均来概括这部小说：一些含义幸存了下来，但细微之处丢失了。

使用模型的上下文序列嵌入（Using the model's contextual sequence embeddings） 一种更有原则的做法是直接从语言模型中提取整个序列的隐藏表示。由于 ESM2 的训练目标是基于周围上下文预测被掩蔽的 token，其内部层为序列中的每个氨基酸都编码了丰富的、上下文化（contextualized）的嵌入。

  • 具体来说，我们可以把一条蛋白质序列送入 ESM2，提取最终隐藏层的激活值，得到一个形状为 (L', D) 的张量，其中 L' 是输出 token 的数量（可能与输入长度 L 不同），D 是模型的隐藏维度（本次为 1,280）。
  • 随后我们沿序列长度做平均池化（mean pooling），得到一个形状为 (D,) 的定长嵌入。虽然取平均看起来过于简单，但它往往出奇地有效——因为模型已经通过自注意力把上下文信息整合进了每个 token 的表示中，池化后的向量仍然捕捉到了贯穿整条序列的有意义依赖关系。

最后这种做法在实践中最为常见也最强大——也正是我们将在下一节中探索的方法。

python
# 本任务沿全部 token 位置取均值，包含特殊 token 和填充位置。
import torch
import numpy as np
from transformers import AutoTokenizer, EsmModel

def get_mean_embeddings(sequences: list[str],tokenizer, model) -> np.ndarray:
    """使用蛋白质语言模型计算每条序列的平均嵌入。"""
    device = torch.device("cuda") if torch.cuda.is_available() else torch.device("cpu")
    # 对输入序列做 tokenization，并填充至等长。
    model_inputs = tokenizer(sequences, padding=True, return_tensors="pt")
    # 把 tokenization 后的输入移动到目标设备（CPU 或 GPU）。
    model_inputs = {k: v.to(device) for k, v in model_inputs.items()}
    # 把模型移动到目标设备，并设置为评估模式。
    model = model.to(device)
    model.eval()
    # 前向传播，不追踪梯度，以获取嵌入。
    with torch.no_grad():
        outputs = model(**model_inputs)
    mean_embeddings = outputs.last_hidden_state.mean(dim=1)
    return mean_embeddings.detach().cpu().numpy()

Preparing the Data 数据准备 ​

许多机器学习书籍和博客文章会尽快直接跳到最令人兴奋的部分——训练和评估模型。但在实践中，训练往往只占整个工作流的一小部分。大量时间花在理解、清洗和结构化数据上。而当模型出问题时，根本原因往往能在数据中找到。所以，与其凭空塞给你一个现成的 CSV，我们将一步步走完数据准备的过程——从真实世界的资源出发，逐步完成把它变成模型可用的东西所需的各个步骤。

我们的目标是在冻结的 ESM2 嵌入之上训练一个分类器，从序列预测蛋白质功能，这意味着我们要组装一个由 (protein_sequence, protein_function) 对构成的数据集。幸运的是，生物学家已经开发出了定义蛋白质功能的系统性框架，并且已经存在经过整理的数据集。其中最广泛使用的资源之一，是 CAFA（Critical Assessment of Functional Annotation，功能注释关键评估）竞赛，这是一个由社区驱动的竞赛，各团队构建模型来预测蛋白质功能。我们将把 CAFA 数据作为我们的原材料，但仍需要自己对其进行处理和结构化。

提示： 如果你熟悉 AlphaFold 和蛋白质结构预测，你可能听说过名字相似的 CASP（Critical Assessment of Structure Prediction，结构预测关键评估），它在蛋白质结构领域扮演着类似的角色。像这样的公开基准，对推动计算生物学众多问题的进展起到了关键作用。

现在让我们来探索 CAFA 数据集。

Splitting the Dataset into Subsets 把数据集划分为子集 ​

我们会把数据集划分为三个不同的子集：

训练集（Training set） 用于拟合模型。模型在训练期间看到这些数据，并利用它来学习模式。

验证集（Validation set） 用于在开发过程中评估模型性能。我们用它来调超参数、比较不同的模型变体。

测试集（Test set） 只在最终评估时使用一次。关键在于，我们避免用这些数据来指导模型设计决策。它充当我们对模型泛化到完全未见过的数据的能力的最佳估计。

我们按 EntryID 来划分蛋白质，确保每个蛋白质只出现在一个子集中：

Converting Protein Sequences into Their Mean Embeddings 把蛋白质序列转换为其平均嵌入 ​

现在我们把每个数据划分子集中的序列转换成相应的平均嵌入，就像我们之前做的那样。由于这一步可能很耗时——尤其是使用更大的模型时——值得想一想如何高效地完成它。使用 GPU 可以显著加速计算，但我们也可以通过「只计算一次嵌入、存到磁盘、之后再加载」来避免重复劳动。

为了让这一过程更方便，我们用一对辅助函数来存储和加载序列嵌入：

python
# 每批 2 条序列，每 100 批存一个分片；先核对已有最终文件和缓存。
import torch
import math
import os
import numpy as np
from transformers import AutoTokenizer, EsmModel
from tqdm.auto import tqdm

def store_sequence_embeddings(sequence_df,store_prefix,tokenizer,model,
    batch_size=2,force=False,save_every_batches=100,keep_cache=False,):
    """分批生成蛋白质嵌入，支持缓存与断点续算。"""

    source = sequence_df.reset_index(drop=True)
    hidden_size = model.config.hidden_size
    columns = [f"ME:{i+1}" for i in range(hidden_size)]
    if set(columns) & set(source.columns):
        raise ValueError("输入中已经包含 ME: 嵌入列，请传入原始数据。")
    #文件路径
    model_name = str(model.name_or_path).replace("/", "_")
    output_dir = BASE_DIR / "2.3-result"
    

    store_file = output_dir / f"{store_prefix}_{model_name}.feather"
    cache_dir = output_dir / f"{store_prefix}_{model_name}_cache"

    def matches(df, expected):
        """核对输入内容、行顺序、嵌入列和数值有效性。"""
        if not df.columns.is_unique or len(df) != len(expected):
            return False
        if [c for c in df.columns if str(c).startswith("ME:")] != columns:
            return False
        if not set(expected.columns).issubset(df.columns):
            return False
        if not df[expected.columns].reset_index(drop=True).equals(
            expected.reset_index(drop=True)
        ):
            return False
        return bool(np.isfinite(df[columns].to_numpy()).all())

    # 在创建缓存和计算嵌入之前，检查最终 dataframe。
    if store_file.is_file() and not force:
        try:
            if matches(pd.read_feather(store_file), source):
                print(f"结果完整，跳过嵌入：{store_file}")
                return
            print(f"已有结果与当前输入不符或不完整：{store_file.name}")
        except Exception as exc:
            print(f"已有结果无法验证，将重新生成：{exc}")

    cache_dir.mkdir(parents=True, exist_ok=True)

    def save_feather(df, path):
        temp = path.with_name(path.name + ".tmp")
        df.reset_index(drop=True).to_feather(
            temp,compression="zstd",compression_level=3,)
        
        os.replace(temp, path)

    n_batches = math.ceil(len(source) / batch_size)
    parts = []
    used_files = []

    with tqdm(
        total=n_batches,
        desc=f"{store_prefix} 嵌入",
        unit="batch",
    ) as pbar:
        for first in range(0, n_batches, save_every_batches):
            end = min(first + save_every_batches, n_batches)
            start_row = first * batch_size
            end_row = min(end * batch_size, len(source))

            # 缓存保留序列，用于防止相同 ID、不同序列误用旧嵌入。
            expected = source.iloc[start_row:end_row][
                ["EntryID", "Sequence"]
            ].reset_index(drop=True)

            part_file = cache_dir / (
                f"part_{first:08d}_{end:08d}.feather"
            )
            part = None

            if part_file.is_file() and not force:
                try:
                    cached = pd.read_feather(part_file)
                    if matches(cached, expected):
                        part = cached
                except Exception:
                    pass

            if part is not None:
                pbar.update(end - first)
            else:
                pending = []

                for i in range(first, end):
                    batch = source.iloc[
                        i * batch_size:(i + 1) * batch_size
                    ]
                    values = get_mean_embeddings(
                        batch["Sequence"].tolist(),
                        tokenizer,
                        model,
                    )
                    pending.append(
                        pd.DataFrame(values, columns=columns)
                    )
                    pbar.update(1)

                part = pd.concat(
                    [expected, pd.concat(pending, ignore_index=True)],
                    axis=1,
                )
                if not matches(part, expected):
                    raise ValueError(
                        f"嵌入结果不完整或存在无效数值：{part_file.name}"
                    )

                save_feather(part, part_file)

            # 汇总时不再保留各分片中的序列副本。
            parts.append(part[["EntryID"] + columns])
            used_files.append(part_file)

    embeddings = pd.concat(parts, ignore_index=True)
    if not embeddings["EntryID"].equals(source["EntryID"]):
        raise ValueError("嵌入结果与输入 ID 顺序不一致。")

    result = pd.concat([source, embeddings[columns]], axis=1)
    if not matches(result, source):
        raise ValueError("最终 dataframe 完整性检查失败。")

    save_feather(result, store_file)
    print(f"已保存 {len(result)} 条序列：{store_file}")

    if not keep_cache:
        for path in used_files:
            try:
                path.unlink(missing_ok=True)
            except OSError as exc:
                print(f"缓存清理失败：{path.name}：{exc}")

        # 只移除空目录，不删除其他残留文件。
        try:
            cache_dir.rmdir()
        except OSError:
            pass

def get_mean_embeddings(sequences: list[str],tokenizer, model) -> np.ndarray:
    """使用蛋白质语言模型计算每条序列的平均嵌入。"""

     #计算每条蛋白质序列的残基平均嵌入。
    model_inputs = tokenizer(
        sequences,
        padding=True,
        return_special_tokens_mask=True,
        return_tensors="pt",
    )

    # special_tokens_mask 仅用于池化，不传给模型。
    special_tokens_mask = model_inputs.pop("special_tokens_mask").to(device)
    model_inputs = {k: v.to(device) for k, v in model_inputs.items()}

    # 有效位置：非 padding，且非首尾等特殊 token。
    residue_mask = (
        model_inputs["attention_mask"].bool()
        & ~special_tokens_mask.bool()
    )
    residue_counts = residue_mask.sum(dim=1, keepdim=True)

    if (residue_counts == 0).any().item():
        raise ValueError("存在不包含有效氨基酸残基的序列，请检查输入。")


    with torch.inference_mode():
        hidden_states = model(**model_inputs).last_hidden_state

        # [批大小, 序列长度, 1]，广播到嵌入维度。
        masked_states = hidden_states.masked_fill(
            ~residue_mask.unsqueeze(-1), 0.0
        )
        mean_embeddings = (
            masked_states.sum(dim=1)
            / residue_counts.to(hidden_states.dtype)
        )

    return mean_embeddings.cpu().numpy()

Training the Model 训练模型 ​

现在我们要在平均蛋白质嵌入之上训练一个简单的多层感知机。回想一下，每条蛋白质序列的长度是可变的，但我们已经把它们转换成了固定大小的嵌入。我们的目标是预测每个蛋白质执行的是 67 种可能的分子功能中的哪些。这是一个多标签分类（multilabel classification）问题，意味着每个蛋白质可以同时与多个功能标签相关联。

在这个设定中，我们将训练一个轻量级的 MLP（multilayer perceptron，多层感知机）——一叠带非线性激活的稠密层。重要的是，我们并不是在微调原始的 ESM2 模型：它保持冻结，我们的模型只是在它的嵌入之上学习。下面是模型代码：

python
# 默认隐藏层为 512 和 256 维，输出维度由标签数决定。
import torch
import torch.nn as nn


class Model(nn.Module):
    """用于蛋白质功能预测的简单 MLP。"""

    def __init__(self, num_targets: int, dim: int = 256):
        super().__init__()
        self.num_targets = num_targets
        self.dim = dim
        self.net = nn.Sequential(
            nn.LazyLinear(dim * 2),
            nn.GELU(),
            nn.LazyLinear(dim),
            nn.GELU(),
            nn.LazyLinear(num_targets),
        )

    def forward(self, x):
        """对输入特征应用 MLP 层。"""
        return self.net(x)

    def create_optimizer(self, dummy_input, lr: float = 0.001):
        """用 dummy input 固化参数形状，并返回优化器。"""
        with torch.no_grad():
            self(dummy_input)
        return torch.optim.Adam(self.parameters(), lr=lr)

关于这个极其轻量的模型，有几点说明：

  • 它用 nn.Sequential 堆叠各层，对这样一个简单模型来说，这让定义保持清晰易读。
  • 我们使用 GELU（Gaussian Error Linear Unit，高斯误差线性单元）激活函数，它是 ReLU 的一种平滑的非线性替代。
  • 最后一层是投影到功能标签数量（num_targets）的 nn.LazyLinear 层。它返回的是 logits 而不是概率——所以我们会在损失函数内部应用一个合适的激活函数（例如 sigmoid），把这些 logits 转换成预测概率。
  • 这个模型冻结在 ESM2 嵌入之上——也就是说它不更新 transformer 的权重。它只学习把固定的嵌入映射到功能标签。这种做法高效、可解释，并能减少训练期间的内存占用。

你可能也注意到，我们在模型类上附加了一个便捷方法 create_optimizer，用来创建优化器与训练所需的状态。它把参数形状推断、参数初始化和优化器设置封装在一起。这一点特别有用，因为它让我们能够在所需的一切——模型、用于形状推断的 dummy input、以及优化器配置——都齐备时，立即构建出优化器。

提示： 上面 PyTorch 版本用 nn.LazyLinear 来复现原书 Flax 模型「根据输入自动推断形状」的行为：各层的输入维度会在第一次前向传播时确定。因此 create_optimizer 先用一次 dummy input 前向传播把参数固化下来，再基于这些参数构建 Adam 优化器——这正好对应原书用 dummy input 做形状推断、并一并完成参数初始化与优化器设置的角色。

Defining the Training Loop 定义训练循环 ​

有了模型和数据集，我们现在可以定义一个执行单次训练步的函数。这一步包括：

  • 一次通过模型的前向传播
  • 计算损失
  • 计算梯度
  • 用这些梯度更新模型参数

下面是实现方式（这里用 PyTorch 的优化器与反向传播完成梯度计算和参数更新）：

python
# BCEWithLogits 将 sigmoid 与二元交叉熵合并计算，输入保持为 logits。
def train_step(model, optimizer, batch):
    """执行一次训练步并更新模型参数。"""
    model.train()

    # 每批分别包含嵌入矩阵和多标签目标矩阵
    embeddings, targets_batch = batch
    embeddings = embeddings.float()
    targets_batch = targets_batch.float()

    # 前向传播。
    logits = model(embeddings)

    # 计算 sigmoid 二值交叉熵损失。
    loss = torch.nn.functional.binary_cross_entropy_with_logits(
        logits, targets_batch
    )

    # 反向传播并更新参数。
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

    return loss

在这个设定中：

  • 我们使用 sigmoid 激活和二元交叉熵损失，这适合多标签分类。logits 经过的是 sigmoid 激活，而不是 softmax——因为对于每一种可能的蛋白质功能，我们想要的是彼此独立的「是/否」预测。记住，每个蛋白质可能同时具有多种功能。
  • 在 PyTorch 中训练步是即时（eager）执行的；如果需要进一步提升性能，可以把模型和数据都放到 GPU 上，并利用自动求导（autograd）高效计算梯度。

接下来，我们用 sklearn 中的工具实现一些指标，以在损失之外评估模型表现：

python
# auprc 键实际保存 average precision；阈值指标用 >= 0.5。
from sklearn import metrics


def compute_metrics(targets: np.ndarray, probs: np.ndarray, thresh=0.5) -> dict[str, float]:
    """计算 accuracy、recall、precision、auPRC 和 auROC。"""
    if np.sum(targets) == 0:
        return {
            m: 0.0
            for m in ["accuracy", "recall", "precision", "auprc", "auroc"]
        }

    return {
        "accuracy": float(metrics.accuracy_score(targets, probs >= thresh)),
        "recall": float(metrics.recall_score(targets, probs >= thresh)),
        "precision": float(
            metrics.precision_score(
                targets,
                probs >= thresh,
                zero_division=0,
            )
        ),
        "auprc": float(metrics.average_precision_score(targets, probs)),
        "auroc": float(metrics.roc_auc_score(targets, probs)),
    }

我们会对每个蛋白质的标签向量追踪以下评估指标：

准确率（Accuracy） 所有标签上预测正确的比例。在像这样数据不平衡的多标签分类中，准确率可能有误导性——大多数标签都是零，所以一个总是预测「无功能」的模型看起来也会很准。尽管如此，它是一个直观的指标，我们暂时把它包含进来。

召回率（Recall） 模型正确预测出的真实功能标签的比例（即 真阳性 / 所有实际阳性）。高召回率意味着模型没有漏掉很多真实功能。

精确率（Precision） 预测出的功能标签中正确的比例（即 真阳性 / 所有预测阳性）。高精确率意味着模型避免了误报。

精确率-召回率曲线下面积（auPRC） 概括了在不同阈值下精确率与召回率之间的权衡。这里名为 auprc 的键实际由 average_precision_score 计算，得到的是平均精确率（AP），并非对 PR 曲线做梯形积分。在像本问题这样高度不平衡的设定中特别有用。

受试者工作特征曲线下面积（auROC） 衡量模型在所有阈值上区分正例与负例的能力。虽然它是一个标准的判别能力指标，但在高度不平衡的数据集中有时会有误导性，因为它对两个类别赋予相同的权重。

在本次多标签设定中，我们沿批次逐行计算，即对每个蛋白质的 67 个功能标签计算指标，再在批次内取平均。虽然函数名保留为 calculate_per_target_metrics，实际并不是按 GO 标签列计算。

我们在评估步 eval_step 中应用这些指标计算：

python
# 下方 zip 沿批次逐行迭代，所以这里实际按蛋白质计算指标。
def eval_step(model, batch) -> dict[str, float]:
    """运行评估步，并返回各蛋白质上的平均指标。"""
    model.eval()
    embeddings, targets_batch = batch
    embeddings = embeddings.float()
    targets_batch = targets_batch.float()
    with torch.no_grad():
        logits = model(embeddings)
    loss = torch.nn.functional.binary_cross_entropy_with_logits(
        logits, targets_batch
    )
    target_metrics = calculate_per_target_metrics(logits, targets_batch)
    metrics = {
        "loss": loss.item(),
        **pd.DataFrame(target_metrics).mean(axis=0).to_dict(),
    }
    return metrics


def calculate_per_target_metrics(logits, targets):
    """为多标签批次中的每个蛋白质计算指标。"""
    probs = torch.sigmoid(logits)
    target_metrics = []
    for target, prob in zip(targets, probs):
        target_metrics.append(compute_metrics(target.numpy(), prob.numpy()))
    return target_metrics

评估会为批次中的每个蛋白质计算指标。对每个蛋白质，我们：

  • 对其 67 个 logits 应用 sigmoid，得到功能概率。
  • 对这些概率做阈值化（例如在 0.5 处），得到二值预测。
  • 把这些预测与真实功能标签比较，计算诸如准确率、精确率、召回率、auPRC 和 auROC 的指标。

我们对批次中的每个蛋白质重复这一过程，然后对得到的指标在各蛋白质上取平均。这告诉我们模型对每个蛋白质预测功能集合的效果如何。它并不报告每个 GO term 的性能。如果我们想要按功能划分的指标（例如模型预测 GO:0003677 的效果如何），就需要改为按列计算指标。

在下一段代码里，一切汇聚成一个 train 函数，而这个基本设定的各种变体会在每一章中反复出现。我们有一个训练循环：先初始化模型与优化器，然后按批次遍历数据集来训练模型，并每隔一段时间评估它：

python
# step 从 0 开始；在 0、30、…、270 步记录完整验证集的批次均值。
import itertools


def train(
    model,
    optimizer,
    dataset_splits: dict[str, DataLoader],
    batch_size: int,
    num_steps: int = 300,
    eval_every: int = 30,
):
    """使用分批的 PyTorch 数据加载器训练模型，并追踪性能指标。"""
    # 创建容器以在训练和评估期间保存计算结果。
    train_metrics, valid_metrics = [], []
    # 训练集无限循环，便于每一步取出批次。
    train_batches = itertools.cycle(dataset_splits["train"])
    steps = tqdm(range(num_steps))  # 带进度条的步数。
    for step in steps:
        steps.set_description(f"Step {step + 1}")
        # 取一批训练数据并进行训练。
        loss = train_step(model, optimizer, next(train_batches))
        train_metrics.append({"step": step, "loss": loss.item()})
        if step % eval_every == 0:
            # 对所有评估批次计算指标。
            eval_metrics = []
            for eval_batch in dataset_splits["valid"]:
                eval_metrics.append(eval_step(model, eval_batch))
            valid_metrics.append(
                {"step": step, **pd.DataFrame(eval_metrics).mean(axis=0).to_dict()}
            )
    return model, {"train": train_metrics, "valid": valid_metrics}

关于这个训练循环，有几点说明：

高效的批次采样（Efficient batch sampling） 训练数据通过无限循环（itertools.cycle）流式提供，确保可以无限地遍历数据。

定期评估（Regular evaluation） 每隔 eval_every 步，模型会在完整的验证集上被评估一次，以便用我们之前定义的指标（例如 auPRC 和 auROC）监控进展。

指标聚合（Metric aggregation） 验证指标按批次计算，然后用 pd.DataFrame(...).mean(axis=0) 在所有批次上取平均。这是批次等权平均；验证集最后一个批次只有 7 条，权重仍与完整的 32 条批次相同，因此不完全等同于对 967 条蛋白质直接求平均。

Thresholded and Continuous Evaluation Metrics 阈值型与连续型评估指标 ​

我们的评估指标分为两类：阈值型（thresholded）与连续型（continuous）。

  • 精确率和召回率是根据二值预测计算的——也就是在给模型输出的概率应用一个固定阈值（通常 >=0.5）之后。

精确率和召回率为 0，而 AP 和 auROC 仍较高，是可能的。当模型给正确的标签分配了更高的概率，但这些概率都低于决策阈值时，就会发生这种情况。此时，阈值型指标显示失败，而基于排名的指标仍然反映出有意义的信号。

如果我们想用当前的阈值型指标来解决这个问题，可以降低决策阈值——例如降到 0.2 或 0.3——以鼓励更多的正例预测。可以在验证集上用 F1 分数（精确率与召回率的调和平均）选择阈值，然后固定该阈值，再做最终测试。这里保留实际运行的 0.5 阈值，没有另行调参。

Evaluating Model Usefulness 评估模型的实用性 ​

我们把模型与两个简单的基线（baseline）进行比较：

抛硬币（Coin flip） 对每个蛋白质功能，以相等概率随机预测 0 或 1。这给了我们一个「完全无知」的基线。

按比例猜测（Proportional guessing） 对每个功能，以其在训练集中的频率作为概率去预测 1。这体现了对先验类别分布的知识，但不含任何学习。

这些基线有助于给模型的性能提供语境。如果我们训练出的模型不能胜过这些简单的启发式方法，那就说明它可能没有从数据中学到有意义的结构。

下面是这些基线的实现：

python
# 两个基线都不使用序列：分别按 0.5 和训练标签频率随机产生二值预测。
def make_coin_flip_predictions(
    valid_true_df: pd.DataFrame, targets: list[str]
) -> pd.DataFrame:
    """为每个蛋白质功能做随机抛硬币预测。"""
    predictions = np.random.choice([0.0, 1.0], size=valid_true_df.shape)
    return pd.DataFrame(predictions, columns=targets, index=valid_true_df.index)


def make_proportional_predictions(
    valid_true_df: pd.DataFrame, train_df: pd.DataFrame, targets: list[str]
) -> pd.DataFrame:
    """做与频率成正比的随机蛋白质功能预测。"""
    percent_1_train = dict(train_df[targets].mean())
    proportional_preds = []
    for target_column in targets:
        prob_1 = percent_1_train[target_column]
        prob_0 = 1 - prob_1
        proportional_preds.append(
            np.random.choice([0.0, 1.0], size=len(valid_true_df), p=[prob_0, prob_1])
        )
    return pd.DataFrame(
        np.stack(proportional_preds).T, columns=targets, index=valid_true_df.index
    )

Improvements and Extensions 改进与扩展 ​

我们构建的模型表明，使用预训练嵌入和一个轻量级分类器，可以从序列预测蛋白质功能。然而，仍有许多方向可以改进、解释和扩展这项工作。我们把这些想法分成两大类：分析驱动的洞见，以及机器学习层面的改进。

选择改进方向之前，可以先明确模型要用于什么场景：

你为什么要做这件事？ 谁会用这个模型，他们实际需要什么？你现在能把这个原型分享给用户，以收集早期反馈吗？

什么时候算完成？ 当前模型已经足够好了吗？哪些具体的改进会有意义地提升它的实用性？这个任务或类似任务有哪些基准？

什么最重要？ 所有功能上的性能同等重要吗，还是你只关心某一特定类别（例如酶与非酶）？相应地聚焦你的优化方向，可以节省时间。

你需要可解释性吗？ 对于某些应用，理解模型为什么做出某个预测，可能比最大化性能更重要。

这些问题有助于决定下一轮实验该改哪些部分。

Biological and Analytical Exploration 生物学与分析层面的探索 ​

即使模型固定不变，我们也可以通过探查它的行为、并与生物学预期作比较，学到更多东西：

阈值调优（Threshold tuning） 我们的结果表明，在默认概率阈值 0.5 下，模型的 AP 高于随机基线，但召回率较低。你可以用像 F1 分数这样的指标（按蛋白质功能或全局地）优化这个阈值，以在精确率和召回率之间找到更好的权衡。

物种泛化（Species generalization） 当前数据集只有人类，但这可能是不必要的限制。试着纳入其他物种的蛋白质-功能对，看看性能是否提升。

功能特异的性能驱动因素（Function-specific performance drivers） 为什么模型在某些功能上表现好（例如 GPCR 活性），在另一些上却表现差（例如肌动蛋白结合）？你可以调查功能流行度、序列长度或其他性质是否与性能相关。

考察蛋白质的多功能性（Examine protein multifunctionality） 模型是否在具有很多功能的蛋白质上更吃力？按注释功能数量把蛋白质分组，并绘制性能（例如 auPRC），看看是否存在趋势。

可能是真实阳性的假阳性（False positives that might be real） 找出模型自信地预测了某个功能、但该功能未被标注的蛋白质。会不会是模型是对的、而注释缺失了？你可能会怎样去跟进这件事？

Machine Learning Improvements 机器学习层面的改进 ​

从机器学习的角度看，有几个方向可以探索：

调优 MLP（Tune the MLP） 我们的模型是运行在冻结嵌入之上的一个小 MLP。试着增加更多层、dropout 或批归一化，在控制过拟合的同时提升容量。

替代的输入编码（Alternative input encodings） 我们使用的是上下文残基表示的平均池化，残基隐藏状态已融合顺序和上下文，但池化后不再显式保留逐位置表示。试着在 token 级嵌入之上使用注意力池化，或者一个小型 1D CNN 或 transformer。

特征工程（Feature engineering） 你可以增强输入，纳入蛋白质长度、物种（如果你扩展到人类之外），甚至像嵌入范数这样的简单统计量。这些额外特征可能帮助模型更有效地区分蛋白质类型。

训练按功能划分的头（Train a per-function head） 可以尝试为每个功能训练单独的模型（或头），并与联合预测所有功能的结果比较。当任务高度不平衡或彼此不相关时，这会有帮助。或者，你也可以把 GO 功能聚类成几个类别，并为每个簇训练一个模型。

分层地预测功能（Predict function hierarchically） 你可以利用 GO 层次结构为预测增加结构——例如先预测宽泛的功能类别，再细化到更具体的类别。

尝试替代的基础模型（Try alternative base models） 你可以插入 Hugging Face 上的其他蛋白质语言模型，或者探索通过拼接来组合来自多个模型的嵌入。

解冻语言模型（Unfreeze the language model） ESM2 的嵌入是在一个通用任务上预训练的。直接为蛋白质功能分类微调该语言模型可能会提升性能，尽管它需要更多算力和更复杂的训练设置。

提示： 根据应用目标安排实验。如果用户更需要可解释性或更广的生物学覆盖面，就优先解决这些问题。
